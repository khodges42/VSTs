# Portable patches and performance mapping

`*.vixen.json` is UTF-8 JSON with `version: 1`, metadata, a complete `synth` object
and `controls`. Files are limited to 64 KiB. Import rejects unknown fields,
unknown versions, invalid enum values and out-of-range/nonfinite numbers rather
than silently clamping an untrusted document. Existing v1 files remain v1;
future schema changes must add an explicit migration and fixtures before accepting
them. No guessed forward compatibility is claimed.

Factory JSON in `factory/vixen/` is generated by `vixen-render --bank factory/vixen`
from `factory.rs`. Built-in factory recipes are immutable source data, independent
of editable user copies. A user file is a full patch, not a reference to a factory
index, so its sound survives factory bank changes.

## Controls and units

Oscillators hold waveform, level, semitone offset (-36..36), unison (1..7), detune,
width, pulse width and PWM. Square is pulse with width 0.5. Detune 1 spreads the
stack to +/- 0.65 semitones. Single-member oscillators stay centered. ADSR times
and glide are seconds; cutoff is Hz; filter-envelope/key/LFO movement is measured
in octaves. Pitch-envelope and bend range are semitones. LFO/delay beat lengths
are quarter notes, not bars. Delay memory accommodates six seconds at the maximum
supported host rate, covering two quarter notes at 20 BPM.

Performance controls are X/Y in [0,1], brightness/resonance/drive/character offsets
in [-1,1], added glide seconds in [0,2], and output in [0,1]. Brightness spans
four octaves either way; character scales decay exponentially by up to four times.
These offsets are separate from the editable patch's base values. Portable saves
store both. Output is saved, but browsing patches deliberately preserves the
current global output setting; host sessions restore output normally.

## Twelve editable routes

Each route has `enabled`, `source` (`X`, `Y`, `Wheel`), `target`, signed `amount`
(-4..4) and `curve` (0.2..5). Base values are the center of X/Y ranges. Negative
depth reverses polarity. Curve changes preserve endpoints.

For X/Y, let `a = 2 * position - 1`:

```
route = sign(a) * abs(a)^curve * 0.5 * amount
```

For wheel: `route = wheel^curve * amount`. Enabled routes add/multiply their
contributions, then engine limits protect the final effective values.

| Target | Effect of one route unit |
| --- | --- |
| Cutoff | Multiply cutoff by 2^4 (four octaves) |
| Resonance | Add 0.4 |
| Drive, Detune, Width, Chorus | Add 1 normalized unit |
| FilterEnv | Add four octaves |
| PitchEnv | Add twelve semitones |
| Pwm | Add 0.4 pulse-width units |
| LfoFilter | Add three octaves of LFO1 filter depth |
| PhaseMod | Add one modulation-depth unit |
| Decay | Multiply envelope decay by 2^2 |
| Delay | Add 0.5 wet mix |
| Reverb | Add 0.4 wet mix |

Thus a cutoff route with amount 1 sweeps +/- two octaves around the patch cutoff.
Multiple routes let a gesture change brightness, resonance and drive together;
both axes can also target the same parameter. Routes are edited in EDIT mode,
validated and applied with the rest of the synth.

## MIDI and session state

X and Y CC numbers are patch data. They must be distinct 0..119; wheel CC1 and
sustain CC64 are reserved. CC input latches an axis; a changed host automation
value or mouse gesture takes it over. The effective MIDI position is displayed
and saved in host state using separate atomic fields. MIDI movement is not
emitted back as host automation recordings; record incoming CC or use host X/Y
automation lanes. Simultaneous gestures/automation follow host event order.

EDIT is a draft editor. APPLY ends old notes and publishes validated synth data;
save/export can also store an unapplied draft as a new patch. Rename and category
edit create new names/folders on the next save; existing files are retained.
Files are never overwritten or deleted from the plugin. Factory defaults can
always be restored. Host state is the applied document plus current controls,
not a reference to the user file, and contains no sample/plugin pointers.
